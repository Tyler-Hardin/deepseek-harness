# Agent Note：Models 页面承载部署默认模型

Status: implemented

[English](2026-10-02-models-page-default-model.md) | 中文

## Problem

共享的 `agent-default-model` 选定，是自身没有选定的会话所回落到的那一层。它一直没有属于自己的控件：输入区的模型切换在选模型时顺带写入它，工作区对话框的“使用全局默认”一行显示着一个任何页面都设不了的值，其余改动都得手工编辑 profile 的 `cordis.patch.yml`。想表达“新会话从模型 X 开始”的用户，只能先打开一个会话并在其中切换模型，或者去配置文档里找那个条目。而管理提供商与模型列表的那个页面——Models 页面——对会话实际从哪个模型开始毫无显示。

## Decision

Models 设置页面在提供商卡片之上新增**默认模型**一行。它读取 Host 的实时目录（`session/modelCatalog`，本就返回 `default`、`groups` 与 `failures`），并通过共享配置表单写入所属命名空间：`ctx.configForms.get('agent-default-model').mutate([set provider, set model, unset reasoningEffort])`。

这次写入归配置接缝所有，而不是新增的 Remote。`agent-default-model` 本身就是持久化所在，而共享表单控制器已经提供修订栅栏、写入队列、把写入结果折回设置镜像，以及被拒后的恢复读取——正是该页面上每张提供商卡片所依赖的同一套机制。命名空间 id 在客户端就地拼写而非导入，理由与其他客户端侧命名空间常量一致：客户端包不得依赖 Host 包。不提供该 id 条目的部署不渲染这一行：把该条目改名的组合仍可经由服务正常工作——工作区覆盖走的正是服务——但会失去这个控件。

每次选择都清除 `reasoningEffort` 是刻意的，也与工作区对话框一致：这一行选的是路由，应套用所选模型自身的默认档位，而不是为另一个模型存下的档位。

与按工作区那一层的配合，靠的是“不写”。这次写入只涉及条目自身的 `provider`、`model` 与 `reasoningEffort`，因此同级的 `workspaceDefaults` 映射绝不会被触碰，带有自己默认模型的工作区也就保住了它。解析顺序不变——已记录路由、工作区覆盖、共享默认——输入区的模型切换也维持既有路由：该工作区有覆盖时写入覆盖，否则写入共享默认。新默认不会被“采纳”进任何已有会话：没有已记录选定的会话，每次请求本就实时读取共享默认，而推送的 `settings/document-updated` 失效通知会刷新输入区的目录。这正是与工作区路径的区别——后者必须改写会话，因为工作区覆盖会在创建时被记录进会话。

## Consequences

线上接口没有变化：没有新增 Remote 方法，也无需重新生成 typert 或 Cordis 目录。`ui-settings-models` 额外注入 `remote.session`，`ModelsSettingsStore` 在页面快照中发布该行的状态。目录读取失败只削弱这一行，不影响它所合并的提供商行；自身模型列表读取失败的提供商会在此行下方点名。

本记录与[按工作区设置的默认模型](../../implemented/feature/2026-08-25-per-workspace-default-model.zh.md)并列——覆盖层与优先级由后者负责，本行只是移动了那条优先级链的底层。

## Alternatives considered

**新增一个与 `workspace.setDefaultModel` 对称的 `session/default-model` Remote。** 否决：这会为一次配置接缝已经拥有、已经加栅栏、已经能恢复的写入，增加线上接口、路由校验与生成物改动的负担。选择器只可能列出实时注册表正在服务的路由，因此工作区那一对所做的校验，防的是目录根本无法呈现的状态；而路由日后消失的默认值，在输入区本就会明确降级。

**按 `ui-settings-subagent` 的做法，在侧边栏 Plugins 页面新增配套配置页。** 否决：部署级的默认模型应当与它所选择的那些模型放在一起。Plugins 页面是插件自身设置的所在，把起始模型埋在那里，恰好丢掉了设立这一行所要的可发现性。

**在设置导航中新增一个分区。** 否决：一个选择器不值得一个导航条目，而想找“我从哪个模型开始”的用户本来就身处 Models 页面。

**把默认选择并入输入区的模型席位。** 否决：那个席位的含义是按会话的。一个控件同时承载两种含义会让手势变得含糊——而共享默认此前那种隐式的输入区写入，正是这种含糊的来源。

**像工作区路径那样，把新默认采纳进每个空白会话。** 否决：没有必要。没有已记录选定的会话每次读取都会派生共享默认，因此输入区无需逐会话写入即可跟随这次改动。

## Testing

单元测试固定了该行从目录与所服务命名空间得出的派生结果、它的选择器行与路由标识，以及精确的三字段写入。Store 测试覆盖加载时的合并、目录失败时仅该行降级、命名空间未被服务时不出现该行，以及一次经由共享表单暂存并重新发布实时目录结果的保存。组件测试覆盖该行的渲染、被拒消息、只读锁定，以及空目录与提供商失败的情形。无密钥的 `models-default-model` Web e2e 在真实线路上驱动真实页面：选择落入 profile 补丁，其后创建的会话——无论位于所连接的工作区内还是所有工作区之外——都从它开始，而再次移动默认值不会动到已有的工作区覆盖。
